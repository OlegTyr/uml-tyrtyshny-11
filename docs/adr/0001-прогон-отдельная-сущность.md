# ADR-0001. Прогон — отдельная сущность, а не поле в НабореТестов

**Дата:** 2026-11-14
**Статус:** принято

## Контекст

Системе нужно хранить историю прогонов: когда запускали, чем закончилось, сколько длилось. Требования ВИ-01 «Запустить набор», ВИ-02 «Посмотреть отчёт» и ВИ-04 «Пометить флаки» предполагают работу с конкретным прогоном, а не только с последним результатом набора.

## Рассмотренные варианты

1. Поле `последнийСтатус : Статус` в классе `НаборТестов` + лог в файле.
2. Отдельный класс `Прогон` с ассоциацией к `НаборТестов`.

## Решение

Вариант 2.

## Последствия

**Плюсы:** возможна история прогонов, фильтрация по дате и статусу, определение флаки по статистике падений за N прогонов, отчёты по трендам. **Минусы:** усложняется модель, при каждом запуске создаётся новый объект, нужна очистка старых прогонов (планировщик). **Что станет неверным, если пересмотреть:** диаграмма классов, автомат `Прогон`, поток объекта, ВИ-02 и ВИ-04.
