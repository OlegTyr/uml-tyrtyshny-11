# ADR-0003. История прогонов хранится в БД, а не в логах

**Дата:** 2026-11-14
**Статус:** принято

## Контекст

История нужна для отчётов (ВИ-02), определения флаки (ВИ-04) и разбора падений. Логи — это текст, не структурированные данные; выборка «сколько раз тест падал за 30 прогонов» по логам дорога и ненадёжна.

## Рассмотренные варианты

1. Хранить историю в лог-файлах (ELK/Splunk), структурировать JSON.
2. Хранить в реляционной БД (`Прогон`, `РезультатТеста`).

## Решение

Вариант 2.

## Последствия

**Плюсы:** быстрые выборки, транзакционность, индексы по `testId` и `status`, возможность JOIN для отчётов, retention через партиционирование. **Минусы:** нужна схема и миграции, объём БД растёт, нужна очистка (планировщик). **Что станет неверным, если пересмотреть:** C4 Container (БД останется для тестов, но история уйдёт в логи), `ИсторияПрогонов` как сервис чтения БД.
