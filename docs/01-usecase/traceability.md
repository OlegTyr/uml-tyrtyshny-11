# Трассировка ВИ на требования FURPS+

| ВИ | Функциональное | Нефункциональное (категория FURPS+) |
|---|---|---|
| ВИ-01 Запустить набор | запуск набора по кнопке и по API CI | отклик API ≤ 500 мс; старт прогона ≤ 2 с при 50 одновременных запросах (Performance) |
| ВИ-02 Посмотреть отчёт | список тестов, статусы, длительности | отчёт доступен не позднее 5 с после завершения прогона (Performance) |
| ВИ-03 Посмотреть историю | фильтр по дате, набору, статусу | хранение истории ≥ 1 год без деградации выборки (Supportability) |
| ВИ-04 Пометить флаки | ручная и авто-пометка по истории | журналирование всех изменений флага ≥ 1 год (Supportability) |
| ВИ-05 Настроить расписание | cron-выражение, выбор набора | срабатывание по расписанию с точностью ±1 мин (Reliability) |
| ВИ-06 Отменить прогон | остановка выполняющегося прогона | отмена ≤ 10 с, без потери уже полученных результатов (Reliability) |
| ВИ-07 Авторизоваться | вход по логину/токену | блокировка после 5 неудачных попыток; журнал входов (Security) |
| ВИ-08 Отправить уведомление | доставка в Slack/почту | доставка ≥ 99% событий, повтор при ошибке (Reliability) |

## Комментарий

Диаграмма ВИ отвечает только на вопрос «что система делает» (буква F). Остальные категории FURPS+ — Usability, Reliability, Performance, Supportability и «+» (ограничения) — фиксируются отдельно: часть здесь, часть — в архитектурных решениях и нефункциональных требованиях.
