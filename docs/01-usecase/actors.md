# Актёры системы автоматического тестирования

| Актёр | Кто это | Первичный? | Зачем приходит в систему |
|---|---|---|---|
| Разработчик | инженер, пишущий код и тесты | да | запустить набор тестов, посмотреть отчёт, разобраться с падением, повторить упавший тест |
| CI-система | внешний сервис (GitHub Actions / Jenkins) | да (по триггеру) | запускать тесты на каждый коммит автоматически |
| Администратор | инженер эксплуатации | да | настроить расписание прогонов, разметить флаки-тесты, отменить зависший прогон |
| Система уведомлений | внешний сервис (Slack / почта) | нет | получает события о завершении прогона и доставляет их людям |

## Комментарии к решениям

- **CI-система — первичный актёр**, потому что у неё есть собственная цель: получить результат проверки сборки. Она не «помогает» разработчику, а действует самостоятельно по триггеру.
- **Система уведомлений — вторичный актёр**: наша система её привлекает, чтобы доставить сообщение. Своей цели в нашей системе у неё нет.
- Один человек может быть двумя актёрами: разработчик с правами администратора — это и «Разработчик», и «Администратор». Актёр — это роль, а не должность.
