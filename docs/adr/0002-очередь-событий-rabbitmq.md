# ADR-0002. Очередь событий RabbitMQ для асинхронной доставки заданий агентам

**Дата:** 2026-11-14
**Статус:** принято

## Контекст

Runner-агенты могут быть недоступны, перегружены или потерять связь. Синхронный вызов «API → агент» создаёт жёсткую связность: если агент упал, API тоже падает. Нужна устойчивость к отказам и возможность масштабировать агенты независимо.

## Рассмотренные варианты

1. Синхронный HTTP-вызов `API → Runner-агент`.
2. Очередь событий RabbitMQ между API и агентами.

## Решение

Вариант 2.

## Последствия

**Плюсы:** API не блокируется на агенте, агенты масштабируются независимо, сообщение не теряется при падении агента (вернётся в очередь), возможна повторная доставка. **Минусы:** добавляется брокер (эксплуатация, мониторинг), появляется eventual consistency (результат не мгновенный), нужна идемпотентность обработки. **Что станет неверным, если пересмотреть:** C4 Container (пропадёт `bus`), динамический вид, `alt-flow.puml` (асинхронные сообщения станут синхронными).
